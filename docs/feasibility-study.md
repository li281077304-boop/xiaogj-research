## 1. 摘要：研究已支持什么，还不支持什么

**技术上可以独立实现教学记录、材料关联、计划和基于证据的 AI 辅助；有条件地连接校管家主数据后，可以进一步提供教师工作入口与教学分析。当前没有证据证明我们已经拥有可持续、获准、完整的数据接入通道，也没有证据支持直接恢复校管家后台或全面替代。**

四种形态均可讨论，价值与成本不同：增强层保留原系统、范围可控；教学操作系统可能产生较强教学过程价值，但依赖持续记录和数据治理；完整管理系统技术上可独立建设，却要承担整套成熟业务规则、迁移与支持责任；AI Agent 能减少页面建设，但不能省掉数据、权限、证据和人工确认。

目前最有潜力的机会是**让已经发生的教学事实能够被下一次备课、交接、复盘与反馈重复使用**。它可以由 A、B 或 D 承载，不足以决定应开发哪一种产品。也可能通过改进现有工具和工作方法解决，而无需另建系统。

本轮公开资料核查补充发现：校管家有[官方开放平台文档](https://api.xiaogj.com/)，列出基础组织、师生、课程、班级、排课等类别。这证明文档存在；**不证明当前机构已开通、可取得全部字段、拥有批量同步权、已获 SLA 或能免费接入**。官方路线因此值得核实，不能再简单称为“完全没有官方接口线索”。

### 2.3 不能推出的结论

不能从前端源码推出服务器源码、数据库、全部权限规则；不能从普通账号登录推出第三方后台集成权；不能从页面出现导出按钮推出已经具备完整关联数据；不能从 AI 总结入口推出其模型质量、证据链或实际使用效果。

“校管家偏强于机构经营/教务，持续教学链存在机会”是用户与本研究的**产品判断**。现网已有点评、总结、作业等入口，因此目前只能说连续关联、真实进度、材料与计划的整合深度尚未证明，不能写成“校管家没有教学记录或 AI”。

## 3. 四种可能形态

这些是可选择、可组合、也可放弃的研究形态，不是阶段序列。

### A. 校管家增强层

**形态**：继续在校管家处理主要业务，用独立小工具、文件加工、材料检索或伴随工作台补充特定任务。增强层不必嵌入原网页，也不必依赖浏览器扩展。

- 能增强：备课时快速找最近记录与材料，整理教师笔记，生成需确认的反馈，减少跨文件/页面寻找信息；已有数据足够时汇总异常线索。
- 数据进入：正式接口、合法导出、自有记录均可能；网页自动化只是一条有条件的候选，不能默认采用。
- 实际价值：改善一个明确、高频的工作动作，教师能立即看到节省的查找、重复整理或写作时间。
- 依赖深度：只处理自有材料时低；依赖实时课表/学员关系时中高；强绑定私有 Web 接口或 DOM 时高。
- 接口不可用后的存续：材料与自有记录工具仍能存在；“今天上谁”等需要实时校管家数据的功能只能展示有时间标记的快照或明确不可用。
- 主要成本/风险：小工具可能变成第二个录入入口；原产品若已有等价能力，增强收益不足。接入与关联成本可能高于小页面本身。

**成立条件**：有可获得的数据或独立材料来源；有一个老师实际愿意使用、且能减少净工作量的任务。

### B. 教学操作系统

**形态**：教学部主要在自研入口看教学相关信息、保存过程记录、查材料和计划；招生、收费、工资等仍由校管家负责。替代深度限于教学过程，不要求接管排课事务。

- 使用价值：跨课次形成持续档案，便于换师交接、个性化计划、学科组复盘和有依据的 AI 分析。
- 技术难度：网页展示可实现；核心难点是数据新鲜度、课程/场次/成员历史、任课关系、校区权限和连续教学事实。
- 完整性要求：不能只有学员姓名和课程名称；至少需要可可靠关联的对象、有效关系和时间状态。排课不能自动等同实际出勤，点名也不能证明掌握程度。
- 替代深度：成为教学入口之后，教师会期待代课、跨科、多教师、多班级、停复课、历史记录和材料授权正常工作，支持责任明显增加。
- 外部数据不可用：自有记录、材料、计划和历史档案可继续工作；外部课表和关系更新停滞时，不能继续当成实时事实。
- 主要成本/风险：大量数据进入但教学事实不产生，形成“漂亮的空档案”；或者两套系统都要填相同内容，导致弃用。

**成立条件**：授权数据入口可持续；教学记录能在正常工作中自然形成；两套系统的事实来源、更新责任和异常处理有明确边界。

### C. 完整教培管理系统

**形态**：独立承担招生、CRM、收费、排课、教务、家校、财务、人事、工资、报表及迁移支持，最终可能替代校管家。

- 技术上：一般管理系统能力可独立实现；当前研究不构成达到校管家成熟度的实证。学校内部系统与多机构 SaaS 的工程量也不同。
- 工程量：除了页面，要定义并持续验证退费/转费/优惠、消课/冲销、账期、工资口径、审批、消息、导入迁移、权限和报表一致性。源码只覆盖部分前端，无法恢复这些后台规则。
- 长期维护：每一次规则调整、异常收费、迁移差异和误操作都要有人支持；备份恢复、审计与业务连续性成为自身责任。
- 数据迁移：表面导入列表不等于保留有效关系、历史余额、合同约束与可核对账目；长期双系统运行会带来对账与责任冲突。
- 潜在价值：若现有 SaaS 长期无法支持非常独特的业务，且有可持续团队与业务负责人，完全控制可能有价值。当前没有证据证明此条件成立。
- 商业判断：避免 SaaS 订阅费本身不足以证明划算，需比较开发、迁移、停机、支持和多年维护的总成本。

**当前判断**：理论上可做，成熟替代的证明与资源条件不足；在中小机构场景下通常是成本最高、差异化最不明确的选项。没有理由因为发现 WTwo 就降低风险等级。

### D. AI Agent 层

**形态**：通过自然语言查询、整理和生成辅助结果，尽量少做传统 CRUD 页面。可以独立处理文件与教学笔记，也可以作为 A 或 B 的入口。

- “今天上谁”：需要及时课表和教师身份；确定性查询即可，大模型主要负责理解提问与组织答案。
- “最近学了什么”：需要真实教学记录；只有排课和课程标题时只能回答安排，不能回答实际学习。
- “最近考试怎样”：需要成绩、考试上下文和可比性；不能把不同难度的原始分数直接当趋势。
- “下节计划/月度总结/家长反馈”：有可靠证据时可生成草稿；教育结论与对外反馈必须由教师确认。
- “三周状态下降/本周异常学生”：先明确缺勤、任务未完成、成绩等可观察指标，再给证据清单；风险排序不等于确定诊断。
- 相比大量 CRUD：入口更轻，可减少页面和检索成本；对精确编辑、批量核对、权限配置、材料浏览，对话不一定更合适。
- 依赖风险：自由对话不能解决数据缺失。自动点击网页会继承 RPA 的不稳定性；让 Agent 处理收费、调课或发布将显著增加风险。

**成立条件**：可审计的数据来源、受约束的查询范围、可追溯证据、明确拒答/缺失信息表现和确认机制。聊天框成本低，可靠 Agent 的数据与验证成本不低。

### 四形态比较

| 形态 | 主要收益 | 必要数据 | 校管家依赖 | 持续使用门槛 | 最主要的代价 |
| --- | --- | --- | --- | --- | --- |
| A 增强层 | 减少具体任务的查找与整理 | 可只用材料/笔记；实时任务需外部数据 | 低至高，取决于任务 | 每次使用有直接收益 | 小工具孤立、重复输入、接口变化 |
| B 教学操作系统 | 连续教学档案与教学入口 | 主数据、课表及持续教学事实 | 对运营数据中高；对自有过程可较低 | 老师愿持续记录，组织明确维护责任 | 同步、权限、历史和流程治理 |
| C 完整管理系统 | 全业务控制与深度定制 | 全量业务、历史、规则、迁移数据 | 完成迁移后可低；迁移期间很高 | 有长期业务与工程支持 | XL 复杂度、对账、迁移、业务连续性 |
| D AI Agent | 用自然语言检索和生成辅助结果 | 有权限且可核验的上下文 | 文件问答低；实时运营高 | 答案可信、校验成本低于人工 | 幻觉、权限、评测、数据不足 |

## 4. 技术可行性分层

| 层级 | 能力与依据 | 不应误读为 |
| --- | --- | --- |
| 已基本证明可行 | 静态整理业务词汇、API 痕迹和前端流程；通过正常界面识别当前账号可见页面结构；公开官方接口文档可阅读；WTwo 排课/考试前端流程有较深证据 | 自研应用已实现、后台业务已恢复、第三方接口已开通 |
| 高概率可行 | 使用有权处理的自有材料做检索/草稿辅助；独立保存教学记录与计划；用已授权且结构足够的文件做有限分析；数据条件成立后展示教师课程与学生历史 | 教师愿使用、AI 已有实测收益、任意导出都能完整关联 |
| 需要验证 | 正式接口开通、授权范围、数据同步许可、身份接入、稳定标识、历史/变更数据、关联字段、导出格式、接口稳定性、教师输入负担 | 181 个源码接口足以解决全部接入 |
| 风险较高 | 私有 Web API 长期集成；无人值守 RPA；跨域登录态/跨校区授权映射；深度排课替代；财务/工资/高风险写操作；无充分上下文的 AI 风险结论 | 前端按钮权限能代替服务端强制校验 |
| 当前不建议 | 依据现有材料宣布全面替代；为完整性复刻全部报表/家校渠道；直接复用无明确许可源码；未获准长期保存浏览器凭据；自动执行收费、退费、调课或发布 | 这些方向永远不能研究；本次判断仅适用于当前证据与组织场景 |

工程上能实现一个功能，与在该机构安全、稳定、经济地运行，是不同的证明要求。

| 已登录 Web API 的授权集成 | 静态路径与身份传递证据强；实际可用及持续集成许可未确认 | 通常比正式契约弱，私有字段/会话可能变化 | 普通登录不等于后台集成权；学校与厂商必要授权需明确 | M–L | L，登录失效与接口变更持续发生 | 若获准且接口支持，可较及时 | 可能接近 UI 所需数据；不保证历史、删除、批量完整 | 高 |
| 产品导出文件 | 多页面导出入口已观察；文件内容与权限未取得 | 有批次边界；格式/列/筛选仍可能变化 | 导出权不自动覆盖任意再利用；需本地受控处理 | S–M | M，人工更新、对账和格式维护 | 批次快照，无法默认实时 | 可能缺关联 ID、历史或取消状态；待样本核对 | 中，停止导出后只剩旧快照 |
| 浏览器自动化 / RPA | 正常 UI 浏览已证明；无人值守提取未证明 | 受 DOM、弹窗、分页、登录、权限变化影响 | 需确认自动化许可与范围；不绕过验证、不扩账号权限 | 演示 S；稳定使用 M–L | L，人工恢复常被低估 | 批次为主；实时性难保证 | 限于页面可见与正常导出；漏页/漏状态可能静默发生 | 很高 |
| 自建数据逐步降低依赖 | 独立记录在工程上高概率可行；组织输入未验证 | 可自控；质量取决于真实使用与责任人 | 仍要限定个人信息和材料处理目的；不自动取得历史迁移权 | M，范围增加可至 L/XL | M–L，录入与维护也属于成本 | 在实际工作入口记录才可能及时 | 可覆盖未来自行产生事实；历史与外部排课不会自动补齐 | 对自有教学事实低；重录外部主数据会增加负担 |

等级为研究判断，不是报价。所有路线的“当前已获授权可用”均为 `UNKNOWN`。技术实时性还要满足业务允许的更新频率；每天批次也可能够用，取决于是否需要处理当天调课。

### 5.2 路线的关键区别

1. **正式 API**：最值得先核实契约。目录存在是积极证据，后续仍要确认具体域名、字段、分页、有效关系、补偿、费用与服务责任；不能用公开凭据说明去申请或猜测他人身份。
2. **授权 Web API**：只有厂商/机构允许且身份方式可支持时才成立。不能把现有浏览器 Cookie、SID 或 Token 复制成长驻服务凭据。
3. **导出**：适合有限、离线研究，但“没有导出的学生”可能是筛选遗漏而不是删除。缺稳定关联时不能用姓名模糊匹配制造确定事实。
4. **RPA**：可辅助少量获准任务，不宜在当前证据下承担关键数据底座。正常页面观察成功只证明有人值守浏览有效。
5. **自建数据**：降低外部依赖的代价是产生、校验和维护数据。不能以“自建”掩盖重复录入或历史断层。

可替换适配层是各形态的技术候选原则：对内保持自己的业务概念，对外转换不同来源。**本报告不定义接口签名、数据库或同步任务。**

## 6. AI 能力：真实价值、输入与责任

### 6.1 四类责任

- **可自动完成**：有明确输入与检查办法的机械整理，如目录归类、记录检索、统计计算、格式整理；很多步骤应由普通程序完成，未必需要大模型。AI 对话只是入口候选。
- **可以辅助**：生成草稿、给材料候选、比较证据、提示缺失与异常，不自动改变正式教学事实。
- **必须教师/负责人确认**：实际进度、掌握情况、教学计划、对外反馈、风险结论；AI 输出不能成为原始学习证据。
- **不适合交给 AI**：凭推测认定学生心理/健康状态、自动惩罚或评价教师、自动决定退费/工资/续费策略、无人确认发布家长内容，以及无充分数据的确定诊断。

“自动完成”限于受控、可检查的低风险步骤，不意味着通用 Agent 可以任意访问或写入系统。

### 6.2 教师场景

| 场景 | 可能价值 | 必须输入 | 自动与人工边界 | 当前判断 |
| --- | --- | --- | --- | --- |
| 备课 | 少翻文件，找相关历史/材料，形成准备提纲 | 已确认进度、教学目标、材料、最近记录 | 自动检索/整理；建议辅助；内容与题目教师确认 | 高概率，材料可得性待核 |
| 课后记录 | 将教师已说/已写的事实整理成可复用笔记 | 教师原始记录；语音处理若使用需另有许可 | 整理可辅助；不可依据课表补造课堂事实；保存前确认 | 高价值候选，录入时间需实测 |
| 学情总结 | 跨课次减少重复写作，并指出证据缺口 | 教学记录、任务/测试、适用时间段 | 草稿辅助；结论必须确认，保留引用 | 数据不足时只能报告不足 |
| 下一节计划 | 将未解决问题转成教学动作候选 | 当前问题、可用课次、材料、目标 | AI 给候选；教师选定与修订 | 不证明计划有效，须课堂反馈 |
| 讲义推荐 | 从已有授权材料中给候选和理由 | 可检索材料目录、版本、学段/科目/目标 | 自动检索；难度匹配辅助；教师确认 | 无目录时整理成本可能大于收益 |
| 作业/家长反馈 | 少写重复结构，保留具体事实 | 已教内容、任务、学生证据与沟通范围 | 草稿辅助；教师确认后才可外发 | 不包括自动发布或内容承诺 |

### 6.3 学科组长场景

| 场景 | 可能价值 | 输入要求 | 责任边界 |
| --- | --- | --- | --- |
| 教学质量 | 找待复核样本和证据缺口 | 可比课程、记录、观察/评课证据 | 可以辅助抽样，不以记录长度/AI评分自动排名教师 |
| 异常学生 | 聚合缺勤、任务未完成、持续困惑线索 | 定义明确的指标、完整时间窗口 | 自动筛查可观察事实；解释原因与处置需负责人确认 |
| 教学进度 | 对比计划与实际，找持续偏差 | 实际记录和计划版本，而不只有排课 | 聚合可自动；快慢是否合理需教师说明 |
| 班级情况 | 找共性问题和学生差异 | 公共教学内容与逐生证据 | 汇总辅助；全班记录不能证明每人掌握 |
| 新教师带教 | 找示例、提醒记录缺口、帮助准备复盘 | 有权使用的样例与指导规范 | 检索/草稿可辅助；不能替代听课、导师判断 |

### 6.4 教学校长场景

| 场景 | 可能价值 | 输入要求 | 责任边界 |
| --- | --- | --- | --- |
| 教学运营 | 汇总未完成任务与趋势，减少手工周报 | 稳定统计口径、时间范围、覆盖率 | 确定性统计可自动；解释与决策人工 |
| 教师负荷 | 看课次、时间、学生量及工作差异 | 课表、实际课时、课型和职责 | 计算可自动；负荷不等于产能/质量，分配需人工 |
| 学生风险 | 给有证据的关注清单 | 出勤、记录、任务/测试及可观察变化 | 风险线索辅助，不能给心理诊断或确定流失断言 |
| 续费风险 | 结合学习体验提供需沟通线索 | 教学事实外还需合同/费用与沟通信息 | 当前数据不足；不能拿学情直接替代续费预测，更不自动推销 |
| 教学质量趋势 | 聚合可比指标，提示哪里缺证据 | 覆盖足够且可比较的质量数据 | 趋势辅助；考试变化与教学因果不能直接等同 |

以上是任务适配判断，没有运行模型或证明收益。可采用的教育 AI 原则需保留人的判断与数据保护；[UNESCO 指南](https://www.unesco.org/en/articles/guidance-generative-ai-education-and-research)强调这些方向，也不能替代本机构对具体工具的评估。

### 6.5 “只做 AI + 数据层”的路线成立吗？

**有条件成立。** 如果重点是查资料、查课表、整理记录和生成草稿，可以用现有文档/表格/工作入口形成数据层，再用自然语言检索，传统管理页面可以很少。纯文件问答甚至不依赖校管家。

需要保留少量明确的结构入口：身份与权限、数据新鲜度、证据查看、记录确认、更正、材料选择和错误处理。它们可以由现有工具承载，不一定新建后台；但无法全部靠无结构聊天代替。

难点在于：提问中的“这个学生”如何可靠定位；老师是否有权看；回答用的是何时的数据；原始笔记有何缺口；模型能否把外部材料中的指令误当执行权限。对话输入或材料内容不能扩大权限。

结论：可以研究**少后台、强数据与证据**，不能承诺“零数据治理、零人工录入、零权限页面”。只读问答与代操作需分开，后者成本和风险明显更高。

## 7. 成本与隐藏复杂度

### 7.1 相对成本口径

`XS`：有界轻量任务；`S`：较小独立能力；`M`：需持续整合和维护；`L`：跨角色/多流程且需稳定治理；`XL`：多业务域、迁移、长期支持和高风险规则。等级不是人天、报价、排期或团队编制。

矩阵假设：单机构内部使用；使用获准数据；A 范围有界；B 承担持续教学入口；C 追求成熟全面替代；D 是可核验的**只读问答/草稿辅助**，不含自动代操作。AI 在 A/B/C 可选，不应为完整性强加。

| 成本维度 | A 增强层 | B 教学操作系统 | C 完整管理系统 | D 只读 AI Agent 层 |
| --- | --- | --- | --- | --- |
| 初始开发 | S–M | L | XL | M |
| 长期维护 | M | L | XL | M–L |
| 数据接入 | S–M；私有集成可至 L | L | XL | M–L；文件型可降至 S |
| UI | S | M–L | XL | S |
| 后端 | S–M | L | XL | M |
| AI | XS–M，按是否使用 | M，可选 | M–L，可选 | L，证据与评测成本 |
| 权限 | M | L | XL | L，范围越自由越复杂 |
| 测试与质量验证 | M | L | XL | L，需答案与权限评测 |
| 运维 | S–M | M–L | XL | M–L |

若 D 变为跨业务自动写入，权限、测试和运维可能进入 XL。若需要多机构 SaaS，隔离、配置、支持与升级成本进一步增加。若正式接口要收费，其费用是额外未知，不能计作免费。

### 7.2 看起来小，实际复杂的能力

| 表面能力 | 实际复杂度 | 当前证据/风险 |
| --- | --- | --- |
| 排课日历 | 学生/教师/教室/日程冲突，草稿与正式课，预检、部分发布、非法字段、复制移动、调课、预约/排队 | E6 已有深证据；日历 UI 只是一部分 |
| “我的学生” | 当前任课、历史班级、换师、代课、跨科、助教、校区授权和有效时间 | 官方 FAQ 已提示历史成员问题；不能仅列班级所有历史学生 |
| “最近上过哪些课” | 安排/取消/点名/撤销/缺勤要区分，历史与教学内容需结合 | 排课与点名文档线索存在；实际掌握仍要自己的证据 |
| 成绩趋势 | 不同考试、满分、难度、缺考、补考、科目和班级不同 | 考试源码存在不等于跨考试可比性已解决 |
| 当前讲义 | 同名版本、页码/题号、课程共用与学生专属、文件可用性和材料授权 | UI 深关联未确认；现有材料目录也待核 |
| 一键同步 | 重复、漏项、乱序、取消、删除、历史有效期、重名、映射与恢复 | 能读单列表不是持续同步证明 |
| 一键总结 | 记录覆盖率、引用版本、事实与推断、缺失信息、修订与复核 | 生成一段流畅文字不能证明可靠 |
| 收费/退费/工资 | 金额口径、转费、优惠、冲销、追溯、账期、规则版本、对账 | 财务期前端不能替代财务与薪酬规则 |

## 8. 约 50 名教师的组织适配

50 名教师需要稳定、清楚且维护得起的工具，**人数本身不构成需要校管家级业务广度的理由**。班课/一对一比例、校区数量、材料现状和换师频率可能比人数更重要，这些尚未定量核查。

- 可能过度建设：完整工资引擎、复杂审批平台、所有经营报表、招生全流程、多套家校消息、通用低代码权限平台，以及因“全系统”而复制每一个页面。
- 每天可能有用的小任务：开课前找到上次问题与下次准备；快速定位一份讲义及版本；把已产生笔记整理好；换师时看连续记录；给家长写一份有事实依据的反馈；让组长少找散落文件。
- 软件应减少教师的净工作量。可以复用已经说/写的事实，显示已知数据，公共课次内容不要求每人重复填，但个体差异不能被自动补全。
- “缺字段”不必都变为必填项。没有明确后续用途、没有负责人消费的记录，可能成为形式主义负担。
- 管理者看到更整齐的表格，不能单独证明教师端价值。需看是否减少备课查找、交接、复盘与反馈劳动。

**净收益判断**：查找/整理/沟通的节省，应超过录入、修正、审核、切换和维护所花的总时间；还要考虑因缺失/错误导致的损失。收益不必都用分钟衡量，但至少需要可观察的改善。

例如，若 AI 草稿需要逐句纠错，教师直接写更快；若一份课后笔记要在三个入口重填，所谓数据完整反而降低使用率；若班课要求逐生重复抄同一讲授内容，录入成本很可能超过收益。这些是需要实测的风险，不是已经观察到的机构事实。

## 9. 机会地图：价值 × 实现难度/依赖风险

纵轴为**实际价值**，横轴为**实现难度/依赖风险**。此处价值是待验证的假设，难度包含数据、授权和维护，不只是 UI 编写。低难度格默认已具备有权处理的材料/记录；没有数据时应移到高难度格。

|  | 难度/依赖风险低 | 难度/依赖风险高 |
| --- | --- | --- |
| **实际价值高** | 值得优先验证：有来源的材料检索；已写笔记结构整理；有证据的反馈草稿；自有记录时间线；换师交接摘要；已有数据的确定性统计 | 长期机会：持续教学档案；实时教师/学生课表关联；个人进度与材料/计划连续关联；可比较成绩分析；学科组异常识别；有审计的跨源 AI 问答 |
| **实际价值低** | 可有可无：装饰性仪表盘；已有导出的简单改版；无复用价值的模板美化；不影响任务的聊天外观 | 当前不要做：复制全部经营报表；成熟财务/工资替代；招生与消息渠道全家桶；仅为省订阅费全面替代；自主 Agent 收费/退费/调课；私有接口与 RPA 承担关键持续数据底座 |

### 9.1 主要机会的条件

| 能力 | 价值假设 | 难度/依赖 | 最重要成立条件 |
| --- | --- | --- | --- |
| 最近记录与材料快速定位 | 高频备课直接收益 | 低–中 | 原始记录可得且有可靠归属 |
| 课后笔记整理与反馈草稿 | 少写重复结构 | 低–中 | 教师已有事实输入，审核净省时 |
| 换师交接/一个月摘要 | 连续性改善 | 中 | 历史足够、来源明确、权限允许 |
| 教师本周学生视图 | 高频，可能减少来回查找 | 中–高 | 新鲜课表、有效成员关系与身份映射 |
| 实际进度/下节准备关联 | 潜在差异化较高 | 中–高 | 教师持续记录且能回到备课使用 |
| 讲义候选与版本定位 | 潜在高频 | 中 | 目录、版本与使用权明确 |
| 组长异常线索 | 可能减少发现滞后 | 高 | 指标可解释、覆盖率够、人工跟进 |
| 教师负荷概览 | 条件性管理价值 | 中 | 不把课次数当唯一负荷标准 |
| 学生/续费风险预测 | 尚未证明真实增益 | 高 | 足够证据、对比基线、人工处置；避免误伤 |
| 全面 ERP 替代 | 当前差异化有限 | 极高 | 独特刚需、团队与长期支持，否则不成立 |

同一能力因数据条件不同可以跨象限。这张地图只指导“哪里值得验证价值”，不安排建设顺序、时间或产品范围。

## 10. 什么情况下这个项目不值得做

以下应作为停止或缩小研究的条件，而不是未来开发要强行克服的清单：

1. **数据长期无法合法、稳定获取**，而所研究的价值又必须依赖实时外部数据。此时实时增强/教学入口不成立；独立材料工具仍可另行判断。
2. **教师不愿或不能持续产生基本教学事实**，已有笔记也无法复用。AI 学情与持续档案就没有可信输入。
3. **重复录入和校验负担超过收益**，系统只增加切换、格式要求和审核工作。
4. **只有管理者觉得有用，教师不使用**；管理报表改善不能掩盖一线负担。
5. **AI 校验时间接近或超过人工完成时间**，缺少证据、经常混淆学生/科目/课次，或者诱导对未发生事实作判断。
6. **维护与支持成本超过现有 SaaS 与现有工具的价值**，且无可持续负责人；不应靠某个人长期救火维持。
7. **必须长期依赖脆弱私有接口或页面自动化**，没有许可、变更通知或故障替代方案，错误更新还难以发现。
8. **责任边界不清**：谁维护关系、谁确认实际进度、谁修正 AI、谁处理错课/停课都无人承担。
9. **没有差异化结果**：校管家现有功能经配置/培训已能解决，或现有表格/材料库足够；另建系统收益不成立。
10. **为了系统完整不断扩大范围**，从教学辅助滑向财务/工资/CRM 全面复制，却没有独特业务需要。
11. **可用数据或材料无法在允许范围内处理**，不得用“技术能做”代替必要权限。
12. **只能展示演示，不能稳定处理真实异常**：换师、改期、退班、缺勤和历史修正反复破坏结果，研究假设需退回重估。

失败应按具体形态判断：实时接口路线失败不自动否定文件辅助；教师输入失败则对 B 与学情型 D 是重大停止信号；全面替代不值得做不等于所有增强都无价值。

## 11. 最大未知数与有界小实验

### 11.1 五个最大未知数

| 未知数 | 为什么决定可行性 | 已有证据/仍缺什么 |
| --- | --- | --- |
| U1 正式接入与持续处理许可 | 决定能否长期取得数据与怎样承担责任 | 官方文档存在；本机构开通、范围、费用、限流、支持及 AI 处理约定未知 |
| U2 数据完整性与业务语义 | 决定回答的是否是真实当前关系与发生事实 | 静态路径/页面标签和公开模型可研究；真实字段、有效成员、历史、取消/撤销、考试/材料覆盖未验证 |
| U3 持续运行与身份稳定性 | 单次可读不能支持每日使用 | 会话与事件机制有线索；身份授权、变更通知、事件补偿、数据新鲜度与恢复能力未知 |
| U4 教师工作习惯与净收益 | 没有事实输入和复用，工具无价值 | 工作稿方向可参考；真实记录分散程度、可复用率、录入/审核时间与持续使用意愿未知 |
| U5 AI 质量与长期承担能力 | 草稿正确、权限可靠、维护有人，才值得长期保留 | 无本机构评测结果、故障记录或总成本基线；维护负责人和能力也未确认 |

### 11.2 值得先用小实验确认的事项

| 研究实验 | 最小边界 | 支持/否定假设的信号 | 实施前提 |
| --- | --- | --- | --- |
| 官方通道条件核实 | 取得厂商已有文档/接入说明，对照实际套餐与机构授权 | 是否清楚支持目标数据、历史、身份、频率、费用与变更责任；缺任一项记为未知 | 联系外部人员须另获用户明确授权；本轮未联系 |
| 导出/正式样本结构核对 | 一个有权处理的范围、一个正常时间窗口；只留脱敏结构 | 是否存在可靠关联、有效关系与时间状态；条目数能否解释；发现缺项可否补齐 | 不自动导出；取得授权样本后在受控位置分析，不上传原件 |
| 正常变化的前后对照 | 两个时间点观察原本会发生的改期/成员变化，无额外修改 | 能否辨认取消、撤销、有效期与历史；无法区分则不支持持续同步假设 | 可先用导出，或正式开通后的受控只读样本；不重放浏览器请求 |
| 教师任务净收益观察 | 少量自愿教师，比较原有备课/记录/交接方式与纸面方案/现有工具 | 查找、整理、确认总时间是否下降；是否愿意重复使用；是否增加双填 | 不需开发，不将真实教师/学生记录放入公开仓 |
| AI 草稿盲评 | 有权使用并去标识的既有记录，或先用虚构样本；与人工/简单模板对比 | 是否引用正确、少编造、纠错后仍省时；数据不足时是否拒绝确定结论 | 模型服务的数据处理范围需明确；真实材料不默认上传外部服务 |
| 有界自动化适配性观察 | 若其他路线不可得，且确认许可后，仅一个正常只读页面 | 是否可发现漏页/中断，需多少人工恢复；失败则降低 RPA 依赖 | 非当前任务，不绕登录，不批量抓取，不产生业务写入 |

这些实验回答是否值得继续研究，不承诺接下来开发；虚构样本只证明流程/文本行为，不能证明真实教师收益和历史数据质量。

### 11.3 已无必要继续大范围调研的内容

- 为确认“系统有招生、财务、报表、家校”再遍历全站：现网地图已有足够证据。
- 为确认“排课是复杂工作流”继续罗列全部按钮：固定源码已给出充分复杂度证据。
- 为证明“课程、学生、班级、老师之间有关联”再搜索更多相似接口名：已经支持研究概念，真正缺的是实际可获字段与语义。
- 试图从前端找完整服务器、数据库和 Token 生成机制：材料边界已清楚，继续寻找不能消除该未知。
- 无明确任务价值地扩大报表/CRM/工资/消息页面清单：对当前研究结论增量小。

是否能合法持续获取数据、某任务是否省时、AI 是否比简单模板有价值，仍值得验证。

## 12. 最终十问

| 问题 | 回答 |
| --- | --- |
| 1. 技术上最多能做到什么程度？ | 独立完整系统理论上可实现；当前证据只证明前端结构与若干流程可研究。成熟替代需要另行重建并验证全部后台规则、迁移、权限和支持，不能据本轮宣布可交付。 |
| 2. 不依赖校管家能做到什么程度？ | 可独立组织有权处理的材料、记录、计划、反馈草稿与证据化 AI。若无其他来源，无法自动获得当前排课/在班关系或完整历史；自建这些数据需承担录入与维护。 |
| 3. 强依赖校管家能做到什么？ | 接入获准且字段够用时，可围绕当前师生/班级/课程/课表做查询、分析和教学入口；仍不能把业务安排当掌握证据，也不自动取得财务/权限等后台实现。 |
| 4. 四模式优缺点？ | A 范围小但易孤立；B 连续教学价值大但数据与记录治理重；C 控制力强但成熟替代总成本最高；D 入口轻但数据、证据、权限与评测成本无法省略。 |
| 5. 哪条路线最有潜力？ | 条件性看，A 的具体任务增强与 D 的只读/草稿辅助较适合验证收益；若持续记录和数据入口成立，B 可能形成长期教学价值。这是机会判断，未选择产品、接入方法或开发。 |
| 6. 最大五未知？ | U1 授权与接入条件、U2 完整性与语义、U3 身份与持续运行、U4 教师净收益、U5 AI质量与维护能力。 |
| 7. 哪些可小实验确认？ | 厂商条件核实、授权样本对账、正常变化对照、教师净收益观察、AI与模板比较；无需开发完整系统。 |
| 8. 哪些无需继续调研？ | 全站广度、排课复杂度、基本实体有关联以及前端无法恢复后台这些结论已有依据；无需再大范围考古。 |
| 9. 是否有只做 AI + 数据层路线？ | 有：有权处理的文件/记录与有限查询可由现有工具承载，AI承担检索和草稿。但身份、纠错、材料选择、证据核验与确认必须有可靠入口；不是全自动聊天替代所有工作。 |
| 10. 是否值得继续研究？ | **有条件值得**：连续教学事实的复用可能有真实价值，正式文档也提供了接入核实入口。继续投入应能减少上述未知；若教师净收益、数据许可或维护条件不成立，合理结果可以是不开发。 |

## 13. 研究边界与交付记录

本报告不选择最终形态，不定义数据库表/业务 API，不承诺同步通道，不确定 V1，不安排开发周期，不宣布进入开发。相对成本、价值象限与组织适配均为 `INFERRED`，需要相关证据才能升级。

现有源码与现网地图保留原样；本轮仅新增研究报告。公开内容不含真实账号、Token、Cookie、SID、人员/学生 ID、姓名、手机号、内部班级/校区数据、经营金额、对话、HAR 或敏感截图。个人与内部工作材料不进入研究仓。

结论允许四种结果：继续验证、收缩到一个任务、用现有工具改善流程、或停止自研；本报告不替用户作最终决定。
