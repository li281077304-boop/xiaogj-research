# Future browser network verification plan

- Source baseline: `chenzhengduan/blog`, commit `5561802e8fc2ed699f30abc59e5e942269660db2`
- Prepared: 2026-10-07
- Current status: plan only; no browser session, login, network request, endpoint replay or credential access occurred during archaeology

## Purpose and boundary

This checklist is for a future session in which the user opens the official product normally and signs in legally with their own authorized account. It observes requests generated by ordinary UI actions. It does not authorize direct API calls, request replay, parameter tampering, account switching, privilege testing, enumeration, automation, scraping, or access to another tenant's data.

Use the exact A–D taxonomy from `api-access-assessment.md`. The goal is to confirm B behavior and fill selected C schema gaps. D items remain out of scope.

- [ ] Confirm the user owns or is authorized to use the account and tenant being observed.
- [ ] Prefer a non-production or low-risk tenant supplied by the user.
- [ ] Agree on read-only UI actions first; do not trigger create, update, publish, delete, export, upload, attendance, finance-lock or scheduling mutations.
- [ ] Create a local evidence folder outside the source repository with restricted permissions.
- [ ] Prepare redaction tokens: `<REDACTED_TOKEN>`, `<REDACTED_COMPANY_ID>`, `<REDACTED_SID>`, `<REDACTED_USER_ID>`, `<REDACTED_PERSON>`, `<REDACTED_PHONE>`, `<REDACTED_RECORD_ID>`, `<REDACTED_URL>`.
- [ ] Do not copy the credential-like value located at `wtwo/vite.config.ts:34-39`.

## Safe capture settings

- [ ] Use browser DevTools Network while performing normal product actions; do not use “Edit and resend,” “Copy as cURL,” replay extensions, scripts, or external proxies.
- [ ] Filter by Fetch/XHR and record only method, redacted origin/path, status, content type, timing, and request/response **field names**.
- [ ] Do not record request/response values for auth headers, cookies, tenant IDs, SIDs, user IDs, names, phone numbers, student/teacher/class/campus data, file URLs, signed URLs or free-text notes.
- [ ] If screenshots are needed, crop to the request name and schema keys after masking all values.
- [ ] Do not export a raw HAR. If a HAR is unavoidable, work on a disposable local copy, remove cookies and all request/response values, verify the sanitized file manually, then delete the raw copy through the user's normal secure process.

## Phase 1 — session bootstrap, read-only

- [ ] Sign in through the official UI; do not inspect or copy the token value.
- [ ] Reload the normal `wtwo` page once.
- [ ] Confirm whether `whoami` is generated by the ordinary page load and record only method/path/status plus top-level response keys. Static expectation: POST `/api/user/whoami` (`wtwo/src/api/index.ts:24-29`; caller `wtwo/src/main.ts:99-137`).
- [ ] Confirm header **presence only** for `WTwo-CompanyID` and `WTwo-AuthToken`; write `present/absent`, never values. Static expectation: `wtwo/src/api/http.ts:6-13`.
- [ ] Confirm whether the application is running as a micro frontend or standalone by behavior only; do not expose the received login object or cookie. Static branches: `wtwo/src/App.vue:60-80`.
- [ ] Record whether success uses `ErrorCode: 200` and whether an expired session is represented by code 407 only if that state occurs naturally; do not manufacture expiry. Static handlers: `wtwo/src/api/handler.ts:6-38`.

## Phase 2 — A-class read flows

Perform only UI actions the user already has permission to view.

- [ ] Open a screen that naturally loads custom fields. Compare method/path and top-level/item field **names** with `IFieldsParams` and `IFieldsModel`; redact all IDs and values. Static evidence: `wtwo/src/api/comm.ts:3-11`; `wtwo/src/types/fields.d.ts:1-15`.
- [ ] Open a normal dictionary-backed selector. Confirm the request key names and `ID/Name/Value/Describe/Status/IsSysDefine` response keys without retaining values. Static evidence: `wtwo/src/api/comm.ts:13-27`; `wtwo/src/types/fields.d.ts:17-24`.
- [ ] Open a timetable view that loads preferences. Confirm GET path, envelope keys and preference field names. Static evidence: `wtwo/src/api/arrange.ts:90-95`; `wtwo/src/types/model/timetable-preference.ts:63-76`.
- [ ] Mark each result `matched`, `drifted`, or `not observed`; do not infer absence from one page load.

## Phase 3 — C-class read-only observations

- [ ] Observe course/calendar/exam list requests generated by ordinary navigation and record only request/response schema keys.
- [ ] For AI history, observe messages/conversations only if the user's normal account already exposes the feature. Record whether SID/header/cookie names are present, not their values. Static evidence: `wtwo/src/api/ai.ts:246-280`.
- [ ] For each C endpoint, note which fields become confirmed and which remain unknown. Keep server semantics, authorization rules and database mapping in D.
- [ ] Do not test upload/STS, streaming prompts, exports, draft publication, attendance, finance operations, create/update/delete, or signed-link navigation during the read-only pass.

## Stop conditions

Stop capture immediately if the browser displays another tenant's data, DevTools exposes a credential in material being saved, the only next step would require replay/tampering, a normal action would alter real business data, the account lacks the relevant permission, or the user cannot confirm authorization. Record only that verification stopped; do not preserve the sensitive response.
